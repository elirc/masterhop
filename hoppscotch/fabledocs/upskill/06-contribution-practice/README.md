# 06 — Contribution Practice

Simulated (and genuinely submittable) work at three levels:

1. [01-good-first-tickets.md](01-good-first-tickets.md) — 16 junior tickets
2. [02-mid-level-feature-tickets.md](02-mid-level-feature-tickets.md) — 10 cross-layer features (design note required before code)
3. [03-senior-build-projects.md](03-senior-build-projects.md) — 6 multi-week projects
4. [04-refactor-and-design-katas.md](04-refactor-and-design-katas.md) — 8 senior katas with self-grading

Contribution realism rules (from the root README, repeated because they're the difference between practice and noise): every change answers *why useful, why small blast radius, which existing pattern it follows, how it's tested, what would make a maintainer reject it.* Every ticket lists its **Interview story potential** — do the work, then write the [STAR worksheet](../08-interview-prep/06-behavioral-star-stories.md) the same day while details are fresh.

Note on this clone: it has no own git remote (see [verification log](../09-reference/verification-log.md)). Practice PRs can be made against your own fork of upstream hoppscotch/hoppscotch; treat drift between this snapshot and upstream as part of the exercise.
