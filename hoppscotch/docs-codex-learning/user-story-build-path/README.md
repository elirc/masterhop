# User Story Build Path

This suite gives you ten realistic feature tickets to implement yourself in Hoppscotch. The stories progress from small UI changes to full-stack and architecture-sensitive work.

Do not start by asking Codex to implement a story. Start by reading the files, writing your own plan, and predicting tests.

## Difficulty Progression

- Stories 1-3: easy, 1-2 files, mostly UI or validation.
- Stories 4-5: medium-easy, 3-4 files, reuse existing data or services.
- Stories 6-7: medium, API/state/validation or integration boundary.
- Stories 8-9: hard, frontend + backend + persistence.
- Story 10: expert, architectural implications.

## Definition Of Done

A story is done when acceptance criteria pass manually, the diff is narrow, tests are added or explicitly justified, and you can explain the changed flow out loud.

## How To Use Codex Without Losing The Learning

Use this model prompt:

```text
"I'm working on Story X. I'm stuck on Y. Here is what I've tried: Z. Do not give me the solution immediately. Ask me questions that help me reason through the problem. Point me to the relevant files and patterns. Give hints in stages."
```

Ask Codex to explain existing patterns before generating code. Ask for review after you make the attempt. Do not blindly paste AI code; require it to cite files and explain why the change belongs there.
